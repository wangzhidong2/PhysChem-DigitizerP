# 多路 ESP32 连接 —— 设计文档（电压模块试点）

> 分支：`feat/multi-channel-voltage`
> 状态：电压模块已实现，其余 5 个模块待推广（见「后续计划」）

## 1. 背景与目标

原上位机每个模块只支持**一路**连接：单个串口线程、单组
`time_data / raw_data / voltage_data`、单条曲线。做「多点同时测量」类实验
（如同时测多个电压点、对比两路电源）时只能开两个模块页面，无法在同一张
图上直接对比。

目标：**连接控制**卡片支持「多路连接」——

1. 卡片内新增「＋ 新建连接」按钮，可添加任意多路；
2. 每一路可**单独选择**「有线串口 / 模拟器」；
3. 每一路有**独立的曲线颜色**（点色块即改色）；
4. 每一路**单独连接 / 断开 / 删除**，互不影响；
5. 多路数据以**主机统一时间戳**记录，叠加画在同一张图上；
6. 先在**电压模块**试点跑通全链路，再复制到其余 5 个模块。

## 2. 核心设计决策（与需求方对齐过的四项）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 连接形态 | 同时连接多路并行采集 | 多点对比实验的核心诉求 |
| 图表形态 | 同一张图叠多条曲线 + 图例 | 量程相同便于直接对比；`ChartPanel` 多曲线能力现成 |
| 实施范围 | 先电压模块试点 | 避免设计返工 6 次；交互确认后再推广 |
| 时间基准 | 主机统一时间戳 | 各 ESP32 开机时刻不同，固件毫秒数不可跨路比较；主机打点天然对齐 |

## 3. 架构

### 3.1 数据模型 `_Channel`（纯 Python，不持 Qt 控件）

```
_Channel
 ├─ id / name        # 稳定 id（信号绑定），显示名（通道N，创建时定序）
 ├─ color            # 曲线颜色（UI 色块 ↔ 图表曲线共用）
 ├─ mode / port      # 'serial' | 'simulator'；串口名
 ├─ thread           # SerialThread / SimulatorThread（每路独立）
 ├─ time_data / raw_data / voltage_data   # 每路独立的数据序列
 ├─ live_window      # deque(maxlen=10) 去皮/实时显示窗口
 ├─ last_sample_s    # 采样间隔过滤用的上次记录时刻（每路独立）
 └─ tare_offset_v / tare_active           # 每路独立去皮零点
```

要点：
- **id 不复用**：删除通道后其 id 永久废弃，避免 Qt 信号 lambda 捕获旧
  通道对象造成的数据串线；
- **UI 行控件**由模块统一保管在 `_rows[channel.id]`，数据模型与控件分离，
  `api_snapshot()` 读数据不触碰任何 Qt 方法（DataService 线程安全约定）。

### 3.2 UI：连接控制卡片

```
┌ 连接控制 ────────────────────────────────────────────┐
│ [＋ 新建连接]  每路连接可单独选择串口/模拟器与曲线颜色…  │
│ ┌─────────────────────────────────────────────────┐ │
│ │ [色块] 通道1 [有线串口▾] [COM3▾] [刷新] [连接] [删除] │ │
│ │ [色块] 通道2 [模拟器▾]                        [断开] [删除] │ │
│ └─────────────────────────────────────────────────┘ │
│ 采样频率: [10 Hz▾]（全部通道共用）                      │
└──────────────────────────────────────────────────────┘
```

- 色块 = `PushButton` + 背景色样式，点击弹 `QColorDialog` 选色；
- 模拟器模式下行内的串口下拉与「刷新」按钮隐藏；
- 「删除」在仅剩一路时禁用（至少保留一路）；
- 通道行随配置持久化（`sensor_config.json` 的 `channels` 列表），
  重启后自动恢复。

### 3.3 数据流与线程

```
SerialThread(COM3) ─┐
SerialThread(COM5) ─┼─ data_received(str) ─→ handle_data(data, ch)
SimulatorThread   ──┘                          │
        每路线程一个，lambda 默认参数绑定通道对象
```

`handle_data(data, ch)` 的多路约定：
- `ERROR:` / `START` 按通道处理，设备出错只断开**这一路**；
- 记录用**主机时间戳**：采集期首个到达样本（任意通道）定为 t=0
  （`time.monotonic()`，存模块级 `_t0_mono`），此后每路每个样本的
  横轴 = 收到时刻 − `_t0_mono`。**不再使用固件时间戳做记录**
  （它只用于 CSV 行格式解析）；
- 采样间隔过滤改为按主机接收时刻、每路独立（原来按固件毫秒差）；
- 实时大字/原始值/ADC 端电压标签带通道名后缀，数据记录每行含通道名。

### 3.4 图表

- `update_chart()` 遍历有数据的通道，各画一条 `c.plot(..., color=ch.color,
  label=ch.name)`，共用横轴；x 范围取全部通道时间并集；
- 图表分析面板（拟合/离群点剔除）作用于**第一条曲线**（即通道 1，
  若有数据）——pyqtgraph 侧沿用「第一曲线为拟合对象」的既有约定；
- 引擎切换（matplotlib/pyqtgraph）自动重放最近一次事务，多曲线同样适用。

### 3.5 去皮（每路独立零点）

`tare_now()` 对**所有有数据流入的通道**分别取最近 10 个采样的均值作为
各自的零点；状态标签逐路显示。`adc_to_voltage(raw, channel=ch)` 按通道
自己的零点扣减。多路时这是物理上必要的：不同 ESP32/电路的空载偏移不同。

### 3.6 CSV 保存（长表格式）

```
channel,timestamp_s,raw_adc,voltage_v
通道1,0.000,123,0.0992
通道2,0.103,-45,-0.0363
```

多路时间轴天然对齐（主机时间戳），Excel 透视/筛选按 `channel` 列分组
即可分析；旧版单通道文件是三列宽表，**格式不兼容**（多路时代用长表，
单路场景同样适用，不再分支维护两种格式）。

## 4. 兼容性

| 接口 | 处理方式 |
|---|---|
| `DataService.connection_info / _apply_connection`（网页端连接管理） | 模块仍暴露 `mode_combo / port_combo` 属性，**指向第 1 路**的行控件；`set_connection('模拟器'/端口)` 作用于第 1 路，`connect=true` 连接全部、断开连接全部 |
| 网页端单曲线图表 | `api_snapshot().points` 仍是**主通道**（数据最多的一路）序列，前端零改动可继续画；新增 `channels` 字段（每路 name/color/connected/points_n/latest_raw）供后续前端做多曲线 |
| MCP 工具 | 同上，`get_snapshot` 可读到 `channels` 明细 |
| 旧版配置迁移 | 无 `channels` 键的旧 `sensor_config.json` 自动迁移为一路通道，顶层 `tare_offset_v / tare_active` 迁入该通道；保存时仍写顶层去皮字段（取第 1 路）供旧版回退 |
| `refresh_ports` / `disconnect_all` / `connect_device` | 方法名保留：刷新全部通道端口列表 / 断开全部 / 连接全部（通用动作表与退出清理不破） |
| 其余 5 个模块 | 完全未动，行为与主分支一致 |

## 5. 已知限制（试点的边界）

1. **采样频率全局共享**：所有通道用同一个 `sample_interval_ms`。各路
   不同频率需要每路一个采样间隔控件，试点从简；
2. **AI 分析只喂主通道序列**：`_ai_data()` 取数据最多的一路作 points，
   其余路的概况写入 params 文字。多路全量喂给模型需要 ChartPanel 的
   AI 数据协议升级（points 结构目前是单序列 `[(t, y), ...]`）；
3. **拟合/离群点剔除只作用于第一条曲线**（见 3.4）；
4. **串口端口可重复选择**：两路选同一个 COM 口会被第二路打开失败
   （pyserial 独占），报错走该路的 ERROR 弹窗。后续可在 UI 上做去重
   提示；
5. **颜色为十六进制字符串**存配置，无命名/透明度支持。

## 6. 验证记录

- `py_compile` 通过；残留属性引用清零；
- offscreen 冒烟：默认建 1 路 → 新建第 2 路 → 双模拟器并行采集
  （各 14+ 点、主机时间轴共享）→ 图表 `spec` 出现两条曲线且颜色
  与色块一致 → 去皮两路独立零点 → CSV 长表落盘 → `api_snapshot`
  含 `channels` 明细 → 单路断开不影响另一路 → `disconnect_all`
  全断 → DataService `set_connection` 兼容路径正常。

## 7. 后续计划

1. **推广**：把 `_Channel` 模式复制到电流 / 力 / pH / 超声波×2
   （力模块需考虑固件 TARE 只对串口有效；超声波双模块为单通道固件，
   多路 = 多个 ESP32）；
2. **网页端多曲线**：`app.js` 按 `channels` 明细渲染 N 条 echarts
   series（颜色用快照里的 `color` 字段）；
3. **每路独立采样频率**（如实验需要）；
4. **AI 多序列协议**：`_ai_data` 支持 `series: [{name, color, points}]`，
   ChartPanel 的 AI 弹窗同步升级；
5. **端口去重提示**：同端口被两路选中时在 UI 上即时提醒。
